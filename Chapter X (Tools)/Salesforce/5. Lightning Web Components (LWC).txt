4. Lightning Web Components (LWC)

Lightning Web Components (LWC) is a modern UI framework in Salesforce built on web standards like ES6+, Custom Elements, and Shadow DOM. It follows a component-based architecture and is optimized for performance.

4.1 Basics
Component Structure (HTML, JS, XML)

Every LWC consists of three core files:

File	Purpose
.html	Defines UI (template)
.js	Handles logic
.js-meta.xml	Metadata configuration (exposure, targets)

Example:

<!-- helloWorld.html -->
<template>
    <h1>Hello {name}</h1>
</template>
// helloWorld.js
import { LightningElement } from 'lwc';

export default class HelloWorld extends LightningElement {
    name = 'Raj';
}
<!-- helloWorld.js-meta.xml -->
<LightningComponentBundle xmlns="http://soap.sforce.com/2006/04/metadata">
    <apiVersion>59.0</apiVersion>
    <isExposed>true</isExposed>
    <targets>
        <target>lightning__AppPage</target>
    </targets>
</LightningComponentBundle>
Reactive Properties

LWC automatically tracks changes in properties and updates the UI.

Primitive fields (string, number, boolean) → reactive by default
Objects/arrays → require care (mutation vs reassignment)

Key concept:

this.name = 'New Value'; // triggers re-render

Old decorator (rare now):

@track obj = {};
4.2 Data Handling
@wire (Reactive Data Fetching)
Automatically calls Apex or Salesforce APIs
Reactive when parameters change
import getAccounts from '@salesforce/apex/AccountController.getAccounts';
import { wire } from 'lwc';

@wire(getAccounts)
accounts;
Imperative Apex Calls
Called manually (button click, event)
Better control over execution
import getAccounts from '@salesforce/apex/AccountController.getAccounts';

handleClick() {
    getAccounts()
        .then(result => {
            this.accounts = result;
        })
        .catch(error => {
            console.error(error);
        });
}

lightning-record-form
A base component for creating, editing, or viewing Salesforce records without writing Apex.

Key Features:
- Automatic form generation based on object fields
- Built-in validation and error handling
- Supports create, edit, and view modes
- Handles record saving automatically

Basic Usage:
```html
<template>
    <lightning-record-form
        object-api-name="Account"
        record-id={recordId}
        fields={fields}
        mode="edit"
        onsuccess={handleSuccess}
        onerror={handleError}>
    </lightning-record-form>
</template>
```

JavaScript:
```javascript
import { LightningElement } from 'lwc';

export default class AccountForm extends LightningElement {
    recordId = '001XXXXXXXXXXXXXXX'; // For edit mode
    fields = ['Name', 'Industry', 'AnnualRevenue'];
    
    handleSuccess(event) {
        console.log('Record saved successfully');
        // Navigate or show toast
    }
    
    handleError(event) {
        console.error('Error saving record:', event.detail);
    }
}
```

Modes:
- "view" - Display record (read-only)
- "edit" - Edit existing record
- "create" - Create new record

Advanced Features:
- Custom field layouts using lightning-layout
- Conditional rendering
- Integration with other components
- Custom validation

Example with Custom Layout:
```html
<template>
    <lightning-record-form
        object-api-name="Account"
        layout-type="Full"
        mode="create"
        onsubmit={handleSubmit}
        onsuccess={handleSuccess}>
        
        <lightning-layout multiple-rows>
            <lightning-layout-item size="6">
                <lightning-input-field field-name="Name"></lightning-input-field>
            </lightning-layout-item>
            <lightning-layout-item size="6">
                <lightning-input-field field-name="Industry"></lightning-input-field>
            </lightning-layout-item>
        </lightning-layout>
        
    </lightning-record-form>
</template>
```

4.3 Events
Custom Events (Child → Parent Communication)
// child.js
this.dispatchEvent(new CustomEvent('myevent', {
    detail: { message: 'Hello Parent' }
}));
<!-- parent.html -->
<c-child onmyevent={handleEvent}></c-child>
handleEvent(event) {
    console.log(event.detail.message);
}
Parent to Child Communication
Use @api decorator to expose properties in child component that parent can set.

Child Component (receives data):
```javascript
import { LightningElement, api } from 'lwc';

export default class ChildComponent extends LightningElement {
    @api message; // Public property set by parent
    
    @api childMethod(data) { // Public method callable by parent
        console.log('Called by parent with:', data);
    }
}
```

Parent Component (sends data):
```html
<template>
    <c-child message={parentMessage}></c-child>
    <lightning-button label="Send Data" onclick={sendDataToChild}></lightning-button>
</template>
```

```javascript
import { LightningElement } from 'lwc';

export default class ParentComponent extends LightningElement {
    parentMessage = 'Hello from parent';
    
    sendDataToChild() {
        // Update reactive property
        this.parentMessage = 'Updated message';
        
        // Or call child method
        this.template.querySelector('c-child').childMethod('Direct call data');
    }
}
```

Complete Example - Bidirectional Communication:

Parent Component:
```html
<template>
    <c-child 
        message={parentData} 
        onchilddata={handleChildData}>
    </c-child>
    <p>Received from child: {childResponse}</p>
</template>
```

```javascript
export default class ParentComponent extends LightningElement {
    parentData = 'Initial parent data';
    childResponse = '';
    
    handleChildData(event) {
        this.childResponse = event.detail.message;
        console.log('Data from child:', event.detail);
    }
    
    updateChildData() {
        this.parentData = 'Updated parent data';
    }
}
```

Child Component:
```html
<template>
    <p>Parent says: {message}</p>
    <lightning-input 
        label="Child Input" 
        value={childInput} 
        onchange={handleInputChange}>
    </lightning-input>
    <lightning-button 
        label="Send to Parent" 
        onclick={sendToParent}>
    </lightning-button>
</template>
```

```javascript
import { LightningElement, api } from 'lwc';

export default class ChildComponent extends LightningElement {
    @api message; // From parent
    childInput = '';
    
    handleInputChange(event) {
        this.childInput = event.target.value;
    }
    
    sendToParent() {
        this.dispatchEvent(new CustomEvent('childdata', {
            detail: { 
                message: this.childInput,
                timestamp: new Date().toISOString()
            }
        }));
    }
}
```

Pub-Sub Pattern
Used for communication between unrelated components
Works when components don’t have direct hierarchy

Typical use:

Utility JS module acts as event bus
4.4 Lifecycle Hooks

Lifecycle hooks control component execution stages.

connectedCallback()
Called when component is inserted into DOM
Used for initialization, API calls
connectedCallback() {
    console.log('Component loaded');
}
renderedCallback()
Called after every render
Useful for DOM manipulation
renderedCallback() {
    console.log('Rendered');
}

Important:
Avoid infinite loops (don’t update reactive data here blindly).

4.5 Navigation & UI
NavigationMixin

Used for navigating between pages, records, apps.

import { NavigationMixin } from 'lightning/navigation';

export default class Example extends NavigationMixin(LightningElement) {
    navigateToRecord() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: '001XXXXXXXXXXXX',
                objectApiName: 'Account',
                actionName: 'view'
            }
        });
    }
}
Toast Messages

Used to show notifications.

import { ShowToastEvent } from 'lightning/platformShowToastEvent';

this.dispatchEvent(
    new ShowToastEvent({
        title: 'Success',
        message: 'Record Created',
        variant: 'success'
    })
);

4.6.1 Decorators Deep Dive

Decorators define how properties behave in LWC.

@api (Public Properties & Methods)
Exposes properties/methods to parent components
Enables parent → child communication
import { LightningElement, api } from 'lwc';

export default class Child extends LightningElement {
    @api message;

    @api publicMethod() {
        console.log('Called from parent');
    }
}

Usage in Parent:

<c-child message="Hello"></c-child>
@track (Reactivity for Objects)
Tracks changes in objects/arrays (legacy but still relevant conceptually)
import { LightningElement, track } from 'lwc';

@track user = { name: 'Raj' };

updateName() {
    this.user.name = 'Kumar'; // may not trigger re-render reliably
    this.user = { ...this.user }; // safe approach
}
@wire (Advanced Usage)

Supports both property binding and function handling.

@wire(getAccounts)
wiredAccounts({ error, data }) {
    if (data) {
        this.accounts = data;
    } else if (error) {
        console.error(error);
    }
}

Reactive parameters:

@wire(getAccounts, { industry: '$industry' })
accounts;

4.6.3 Performance Optimization
Key Strategies
1. Minimize Apex Calls
Use caching (@AuraEnabled(cacheable=true))
Prefer @wire when possible
2. Efficient Rendering
Avoid unnecessary re-renders
Use conditional rendering:
<template if:true={isVisible}>
3. List Rendering Optimization

Always use key:

<template for:each={accounts} for:item="acc">
    <div key={acc.Id}>{acc.Name}</div>
</template>
4. Lazy Loading

Load components/data only when needed (tabs, modals)

4.6.4 LWC vs Aura
Feature	LWC	Aura
Performance	Fast (native JS)	Slower
Syntax	Modern (ES6+)	Custom
Debugging	Easier	Complex
Future	Recommended	Legacy

Conclusion:

Always prefer LWC unless Aura is specifically required
4.6.5 Security
Locker Service / Lightning Web Security (LWS)

Salesforce enforces strict security isolation.

Key Concepts:
DOM isolation (Shadow DOM)
No direct global access (window/document restrictions)
Secure communication between components
Best Practices
Avoid direct DOM manipulation
Use standard APIs
Never trust client-side data
